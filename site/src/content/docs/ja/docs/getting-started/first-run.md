ターミナルでコマンドを 1 つ実行し、`https://droid.devpier.dev/app/` を開き、Chrome に聞かれたらローカルネットワークへのアクセスを許可します。

## 1. ゲートウェイを起動する

```sh
curl -fsSL https://droid.devpier.dev/install.sh | sh
```

必要に応じてゲートウェイをインストール（または更新）し、起動します。[インストール](/ja/docs/getting-started/install/)を参照してください。インストール後は `droidpier start` でも起動できます。

ゲートウェイはバックグラウンドで動きます。ターミナルウィンドウは閉じてかまいません。

ゲートウェイはデフォルトで `127.0.0.1`、ポート `7300` をリッスンします。別のポートを使用する場合は[コマンドライン](/ja/docs/reference/cli/)を参照してください。

## 2. Android SDK の確認を行う {#2-let-it-check-your-android-sdk}

<!-- verify: phase 3 -->
起動時に、ゲートウェイはデバイスを起動できるかを確認します。必要なのは Android エミュレーター（`emulator`）、`platform-tools` の `adb`、そしてシステムイメージが入っている仮想デバイス（AVD）が少なくとも 1 つです。Android のバージョンは問いません。不足しているものがあれば、ターミナルに項目ごとに表示し、ページで設定を完了するよう案内します。ターミナルでは何も質問しません。

ゲートウェイがバックグラウンドで動いているときは、この一覧はログに書かれます。`droidpier logs` で確認できます。

<!-- verify: phase 3 -->
ページにも同じ一覧が、各項目のダウンロードサイズとともに表示されます。デバイスを起動できる状態なら、何も表示されません。

| 不足しているもの | ページでの操作 |
|---|---|
| `emulator`、`platform-tools`、システムイメージ | 項目の横のボタンで 1 つずつ、またはまとめてインストールします。システムイメージが 1 つもない場合は Android 14（`system-images;android-34;google_apis;arm64-v8a`）を提案します。デバイスのシステムイメージが削除されている場合は、そのデバイス名を示し、そのイメージを提案します。 |
| デバイスがない | デバイスを作成します。デバイスのモデルと Android のバージョンを選びます。システムイメージがすでに入っていれば、Android 14 をダウンロードする代わりにそれを提案します。 |

Java やコマンドラインツール（`sdkmanager`、`avdmanager`）は不要です。ゲートウェイは各パーツを Android Studio と同じ Google の SDK リポジトリからダウンロードし、SDK フォルダーがまだなければ作成します。

<!-- verify: phase 3 -->
ページで確認するまで、何もダウンロードも作成もされません。開始前に、ページはダウンロードする内容、保存先、必要なディスク容量を表示します。各ダウンロードの前に Google のライセンスを全文表示し、同意した項目だけがインストールされます。ゲートウェイは Android Studio と同じように、同意を SDK の `licenses` フォルダーに記録し、展開する前に各ダウンロードを Google が公開しているチェックサムと照合します。

自分でインストールしたい場合は、ページでその項目の下にある手動インストールの欄を開きます。Android Studio のどこで入れられるかと、インストール先が書かれています。

## 3. ページを開く {#3-open-the-page}

<!-- verify: phase 3 -->
Chrome または Edge で `https://droid.devpier.dev/app/` を開きます。ゲートウェイは起動時にもこのアドレスを表示し、デフォルトブラウザで開きます。デフォルトブラウザが Chrome または Edge でない場合は、このアドレスを自分で Chrome または Edge で開いてください。

ページは自動で接続します。応答するゲートウェイがない間は 1 秒ごとに確認し、ゲートウェイが起動するとすぐに、再読み込みなしで接続します。タブがバックグラウンドにある間は確認しません。

ゲートウェイがポート `7300` 以外で動いている場合、表示されるアドレスの末尾は `#port=<port>` になります。

```text
https://droid.devpier.dev/app/#port=7301
```

ページが正しいポートを見つけられるよう、そのアドレスを開いてください。

## 4. ローカルネットワークアクセスを許可する {#4-allow-local-network-access}

<!-- verify: phase 3 -->
ページが Mac 上のゲートウェイに初めて接続するとき、Chrome は `droid.devpier.dev` がローカルネットワークにアクセスしてよいかを尋ねるパーミッションプロンプトを表示します。**許可**をクリックしてください。Chrome はそのサイトの選択を記憶します。

拒否した場合は[トラブルシューティング](/ja/docs/guides/troubleshooting/#chrome-blocked-local-network-access)を参照してください。

## 5. エミュレーターを使う

gRPC が有効なエミュレーターがすでに起動中であれば、ページにその画面が表示されます。

<!-- verify: phase 2 -->
そうでなければ、リストからデバイスを選んで起動してください。[デバイス](/ja/docs/guides/devices/)を参照してください。

画面をクリックしてキーボードフォーカスを与えます。その後：

- クリックでタップ、ドラッグでスワイプ。
- Mac のキーボードで入力。[キーボードと入力](/ja/docs/guides/keyboard-and-input/)を参照してください。
- 画面上部の戻る・ホーム・履歴ボタンを使用。

## 停止する

`droidpier stop` を実行します。ターミナルウィンドウで `droidpier` を使って起動した場合は、そのウィンドウで `Ctrl+C` を押します。実行中のエミュレーターは動き続けます。次に同じコマンドか `droidpier start` でゲートウェイを起動すると、再び接続します。

## ローカルフォールバックページ

ゲートウェイは同じページを `http://127.0.0.1:7300/app/`（または選択したポート）でも提供します。公開ページが読み込めない場合や接続できない場合に使用してください。

公開ページではなくローカルページをゲートウェイに開かせるには、`--local` を付けて起動します。

```sh
droidpier --local
```
