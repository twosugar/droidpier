ターミナルでコマンドを 1 つ実行してそのウィンドウを開いたままにし、`https://droid.devpier.dev/app/` を開いて、Chrome に尋ねられたらローカルネットワークアクセスを許可します。

## 1. ゲートウェイを起動する

```sh
curl -fsSL https://droid.devpier.dev/install.sh | sh
```

必要に応じてゲートウェイをインストール（または更新）し、起動します。[インストール](/ja/docs/getting-started/install/)を参照してください。インストール後は `droidpier` でも起動できます。

ゲートウェイはそのターミナルウィンドウで動き続けます。ページを使っている間はウィンドウを開いたままにしてください。

ゲートウェイはデフォルトで `127.0.0.1`、ポート `7300` をリッスンします。別のポートを使用する場合は[コマンドライン](/ja/docs/reference/cli/)を参照してください。

## 2. Android SDK の確認を行う {#2-let-it-check-your-android-sdk}

<!-- verify: phase 3 -->
起動時、ゲートウェイは Android SDK、`cmdline-tools`、`emulator`、`platform-tools`、システムイメージ `system-images;android-34;google_apis;arm64-v8a`、そして少なくとも 1 台の仮想デバイス（AVD）があるかを確認します。不足しているものがあれば、ターミナルに項目ごとに手動インストール用のコマンドを添えて表示し、ページでセットアップを完了するよう案内します。ターミナルで質問はしません。

<!-- verify: phase 3 -->
ページにも同じ一覧が、各項目のダウンロードサイズとともに表示されます。

| 不足しているもの | ページでの操作 |
|---|---|
| Android SDK、`cmdline-tools`、`emulator`、`platform-tools`、システムイメージ | 項目の横のボタンで 1 つずつ、またはまとめてインストールします。 |
| AVD がない | デバイスを作成します。デバイスのモデルと Android のバージョンを選びます。 |
| Java（必要な項目がある場合） | Java を含む Android Studio、または JDK 17 以降をインストールしてから、ページを開き直します。ゲートウェイは Java をインストールしません。 |

<!-- verify: phase 3 -->
ページで確認するまで、何もダウンロードも作成もされません。開始前に、ページはダウンロードする内容、保存先、必要なディスク容量を表示します。インストール中は Google のライセンスを全文表示し、同意した項目だけがインストールされます。バージョン 23 以降のコマンドラインツールは、確認なしでライセンスに同意することがあります。その場合は確認の前にページが知らせます。

たとえば、システムイメージを手動でインストールするには次のコマンドを実行します。

```sh
sdkmanager "system-images;android-34;google_apis;arm64-v8a"
```

## 3. ページを開く {#3-open-the-page}

<!-- verify: phase 3 -->
Chrome または Edge で `https://droid.devpier.dev/app/` を開きます。ゲートウェイは起動時にもこのアドレスを表示し、デフォルトブラウザで開きます。デフォルトブラウザが Chrome または Edge でない場合は、このアドレスを自分で Chrome または Edge で開いてください。

ページは自動で接続します。応答するゲートウェイがない間は 1 秒ごとに確認し、ゲートウェイが起動するとすぐに、再読み込みなしで接続します。タブがバックグラウンドにある間は確認しません。

ゲートウェイがポート `7300` 以外で動いている場合、表示されるアドレスの末尾は `#port=<port>` になります。

```text
https://droid.devpier.dev/app/#port=7301
```

ページが正しいポートを見つけられるよう、そのアドレスを開いてください。

## 4. ローカルネットワークアクセスを許可する {#4-allow-local-network-access}

<!-- verify: phase 3 -->
ページが Mac 上のゲートウェイに初めて接続するとき、Chrome は `droid.devpier.dev` がローカルネットワークにアクセスしてよいかを尋ねるパーミッションプロンプトを表示します。**許可**をクリックしてください。Chrome はそのサイトの選択を記憶します。

拒否した場合は[トラブルシューティング](/ja/docs/guides/troubleshooting/#chrome-blocked-local-network-access)を参照してください。

## 5. エミュレーターを使う

gRPC が有効なエミュレーターがすでに起動中であれば、ページにその画面が表示されます。

<!-- verify: phase 2 -->
そうでなければ、リストからデバイスを選んで起動してください。[デバイス](/ja/docs/guides/devices/)を参照してください。

画面をクリックしてキーボードフォーカスを与えます。その後：

- クリックでタップ、ドラッグでスワイプ。
- Mac のキーボードで入力。[キーボードと入力](/ja/docs/guides/keyboard-and-input/)を参照してください。
- 画面上部の戻る・ホーム・履歴ボタンを使用。

## 停止する

ゲートウェイを実行しているターミナルで `Ctrl+C` を押すか、そのウィンドウを閉じます。起動中のエミュレーターはそのまま動き続けます。次回、同じコマンドまたは `droidpier` でゲートウェイを起動すると、再び接続されます。

## ローカルフォールバックページ

ゲートウェイは同じページを `http://127.0.0.1:7300/app/`（または選択したポート）でも提供します。公開ページが読み込めない場合や接続できない場合に使用してください。

公開ページではなくローカルページをゲートウェイに開かせるには、`--local` を付けて起動します。

```sh
droidpier --local
```
