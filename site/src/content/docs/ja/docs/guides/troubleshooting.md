## Chrome がローカルネットワークアクセスをブロックした {#chrome-blocked-local-network-access}

<!-- verify: phase 3 -->
`droid.devpier.dev` のページは、あなた自身の Mac 上のゲートウェイに接続します。Chrome は初回に許可を求めます。拒否した場合、ページは接続できず、何度か失敗した後に Chrome が Mac へのアクセスをブロックしたと表示します。

再度許可するには：

1. Chrome の **設定 → プライバシーとセキュリティ → サイトの設定** を開きます。
2. `droid.devpier.dev` を見つけ、ローカルネットワークアクセスを許可します。
3. ページを再読み込みします。

それでも接続できない場合は、[ローカルフォールバックページ](#use-the-local-fallback-page)を使用してください。

## ポートがすでに使用中

ゲートウェイはデフォルトでポート `7300` をリッスンします。

ゲートウェイが動いている間にもう一度コマンドを実行すると、2 つ目は起動せず、droidpier がすでにポート `7300` で動いていると表示してページを開きます。そのページを使うか、先に `Ctrl+C` で動いているゲートウェイを停止してください。

別のプログラムがポートを使用している場合、ゲートウェイはそのことを表示し、別のポートを提案して終了します。そのプログラムを探すには：

```sh
lsof -nP -iTCP:7300 -sTCP:LISTEN
```

そのプログラムを停止するか、別のポートでゲートウェイを起動します。

```sh
curl -fsSL https://droid.devpier.dev/install.sh | sh -s -- --port 7301
```

インストール後は `droidpier --port 7301` でも同じです。

<!-- verify: phase 3 -->
ゲートウェイは開くアドレスに新しいポートを含めるため、ページは正しいポートに接続します。

## エミュレーターが見つからない

ページが起動中のエミュレーターが見つからないと表示する場合：

- エミュレーターが起動していることを確認します：`adb devices` に `emulator-5554` などが表示されるはずです。
- gRPC を有効にして起動したことを確認します（`-grpc <port>`）。ゲートウェイは gRPC なしのエミュレーターの画面を読み取れません。

<!-- verify: phase 2 -->
ページのリストからデバイスを起動することもできます。[デバイス](/ja/docs/guides/devices/)を参照してください。

エミュレーターが見つからなくてもゲートウェイは動き続け、理由をターミナルに表示します。

<!-- verify: phase 3 -->
ゲートウェイが Android SDK・`emulator`・`platform-tools`・システムイメージの不足を報告した場合は、表示された修正方法に従ってください。[初回起動](/ja/docs/getting-started/first-run/#2-let-it-check-your-android-sdk)を参照してください。

## "sdkmanager" が見つからない

<!-- verify: phase 3 -->
Android Studio でインストールした SDK には、`sdkmanager` と `avdmanager` を含む `cmdline-tools` が入っていないことがあります。ページからインストールできます。不足項目の一覧でその横にあるインストールボタンか、デバイス作成のダイアログを使います。確認すると、ゲートウェイが Google からコマンドラインツール 22.0 をダウンロードして SDK に配置します。ページは Google のライセンスを全文表示し、同意した場合にだけインストールします。

`sdkmanager` には Java が必要です。Java がない場合は、Java を含む Android Studio、または JDK 17 以降をインストールしてから、ページを開き直してください。

手動でインストールする場合は、developer.android.com から Google のコマンドラインツールをダウンロードし、次のパスが存在するように展開してください。

```text
<your SDK>/cmdline-tools/latest/bin/sdkmanager
```

## ページが接続しない

<!-- verify: phase 3 -->
ページは 1 秒ごとにゲートウェイを確認し、応答があるとすぐに接続します。待機したままの場合：

- コマンドを実行したターミナルウィンドウがまだ開いているか確認します。ウィンドウを閉じるか `Ctrl+C` を押すとゲートウェイは停止します。もう一度コマンドを実行すると起動します。
- Chrome が `droid.devpier.dev` にローカルネットワークアクセスを許可していることを確認します。[Chrome がローカルネットワークアクセスをブロックした](#chrome-blocked-local-network-access)を参照してください。
- `--port` を指定してゲートウェイを起動した場合は、表示されたアドレス（末尾が `#port=<port>`）を開きます。
- タブを前面に表示します。タブがバックグラウンドにある間、ページは確認を行いません。

## インストールコマンドが失敗する

- **チェックサムの照合に失敗：** ダウンロードしたファイルがチェックサムと一致しなかったため、何もインストールされていません。もう一度コマンドを実行してください。
- **ダウンロードサイトに接続できない：** Droidpier がインストール済みなら、コマンドは警告を表示して、インストール済みのバージョンを起動します。まだインストールしていない場合は、インターネット接続を確認してからもう一度コマンドを実行してください。

## ページがゲートウェイまたはページの期限切れを表示する

<!-- verify: phase 3 -->
- **ゲートウェイの期限切れ：** ページが表示するアップグレードコマンドを実行してください。[インストールコマンド](/ja/docs/getting-started/install/)と同じです。
- **ページの期限切れ：** Cmd+Shift+R でページを強制再読み込みしてください。

## ブラウザが正しくない

<!-- verify: phase 3 -->
このページは Chrome と Edge でのみ動作します。他のブラウザでは切り替えを求め、接続を試みません。[ブラウザサポート](/ja/docs/reference/browser-support/)を参照してください。

## ローカルフォールバックページを使う {#use-the-local-fallback-page}

ゲートウェイは同じページを `http://127.0.0.1:7300/app/`（または選択したポート）でも提供します。公開ページが読み込めない場合やローカルネットワークアクセスが拒否された場合に使用してください。

`droidpier --local` を実行すると、ゲートウェイは公開ページではなくローカルページを開きます。

## 画面が更新されなくなった

エミュレーターが終了または再起動すると、ページに切断が表示されます。ゲートウェイは動き続けます。エミュレーターが戻ると、ページが再接続して画面も復帰します。
