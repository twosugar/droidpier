`droidpier mcp` は、Model Context Protocol (MCP) に対応した AI クライアント（Claude Code など）をゲートウェイに接続します。クライアントはページが表示するデバイスを操作できます。H5 ページの一覧表示、ページ内での JavaScript 実行、コンソールの読み取り、スクリーンショットの取得が可能です。

クライアントは独自のデバッグ接続を開くのではなく、ゲートウェイを経由します。これは iOS シミュレーターで重要です。WebKit はページに同時にアタッチできるデバッガーを 1 つに限定しているため、別のツール（iwdp など）とページの H5 コンソールが互いを切断してしまいます。ゲートウェイを経由することで、AI クライアントと H5 コンソールが 1 つの接続を共有します。

## 必要なもの {#what-you-need}

- ゲートウェイが動作中であること。バックグラウンド（`droidpier start`）またはターミナルウィンドウのいずれか。バックグラウンドのゲートウェイは自動更新されます。MCP には 2026-11-24 以降に公開されたバージョンが必要です。ターミナルウィンドウで実行しているゲートウェイを更新するには、インストールコマンドをもう一度実行してください。
- ページが開いていて、クライアントに使わせたいデバイスが表示されていること。

## クライアントへの追加 {#add-it-to-your-client}

Claude Code では、一度だけ追加します。

```sh
claude mcp add droidpier -- droidpier mcp
```

その後、新しい Claude Code セッションを開始してください。ツールは `mcp__droidpier__…` として表示されます。

他のクライアントは、コマンドとして実行され標準入出力で通信するサーバーを使用します。Dock から起動したアプリは `PATH` に `~/.local/bin` が含まれない場合があるため、実行可能ファイルのフルパスを指定してください。

```json
{
  "mcpServers": {
    "droidpier": { "command": "/Users/<あなた>/.local/bin/droidpier", "args": ["mcp"] }
  }
}
```

ゲートウェイが別のポートで動作している場合は追加します: `droidpier mcp --port 7310`。

## ツール {#the-tools}

| ツール | 機能 |
|---|---|
| `device_status` | ページが表示するデバイス: 名前、プラットフォーム（`android` または `ios`）、種類、ピクセル単位の画面サイズ。 |
| `list_pages` | そのデバイス上の H5 ページ。各ページに `page` 値、タイトル、アドレス、アプリ、フォアグラウンドかどうかが含まれます。 |
| `evaluate` | ページで JavaScript 式を実行し、結果を JSON で返します。Promise を待ちます。式がエラーをスローすると、ツールはそのエラーで失敗します。 |
| `console_logs` | ページのコンソール出力と未捕捉エラー。ツールがそのページを初めて使用したときに収集が始まります。iOS シミュレーターでは以前にログ記録されたメッセージも含まれます。最後の 500 件を保持します。前回の回答の `next` 値を `since` として渡すと、新しい行だけを取得できます。 |
| `screenshot` | デバイスの画面を PNG 画像として返します。 |

`evaluate` と `console_logs` は `list_pages` の `page` 値を使います。指定しない場合はフォアグラウンドのページを使用します。複数のページがフォアグラウンドにある場合は失敗し、選択できるページの一覧を返します。

## どのデバイスとページを使うか {#which-device-and-which-pages}

ツールは常にページが表示するデバイスを使用します。別のデバイスを使用するには、ページでそのデバイスに切り替えてください。ページが開いていない場合は、ゲートウェイが最後に接続したデバイスを使用し、なければその旨を通知します。

ページはデバイスがデバッガーに表示を許可しているものです。

- Android エミュレーターおよびスマートフォン: Chrome タブ、および WebView デバッグを有効にしたアプリの WebView。
- iOS シミュレーター: Safari タブ、および `isInspectable` を設定した `WKWebView`（iOS 16.4 以降）。

## H5 コンソールと並行して使用する {#using-it-next-to-the-h5-console}

AI クライアントとページの H5 コンソールは同じページを同時にデバッグできます。クライアントが記録したものも H5 コンソールに表示されます。

クライアントも使用している iOS シミュレーターページで H5 コンソールを開いたり閉じたりすると、ゲートウェイはページのデバッグ接続を再度開いて、コンソールがクリーンな状態で起動し、何も残らないようにします（次のページが読み込まれる前のポーズなど）。その瞬間に実行中のツール呼び出しは失敗します。クライアントはそれを再実行できます。

ゲートウェイが再起動した場合（例: 自動更新）、`droidpier mcp` は実行を続け、最大 1 分間ゲートウェイが戻るまで再接続を試みます。その瞬間に実行中の呼び出しは失敗します。

## セキュリティ {#security}

`droidpier mcp` は Unix ソケット `~/Library/Application Support/Droidpier/mcp-<port>.sock` を通じてゲートウェイに接続します。そのフォルダーを開けるのはあなたの macOS ユーザーだけです。ゲートウェイはこれのためにネットワークポートを開かず、ウェブページからもアクセスできません。

あなたのユーザーとして実行される任意のプログラムがこのソケットを使用できます。`adb` や `simctl` を自分で実行するのと同様です。これらのツールを持つクライアントは、あなたのデバイスの H5 ページ（ログイン済みのページを含む）で任意の JavaScript を実行できます。コードを実行する他のツールと同じ方法で、クライアントのツールを許可してください。

ゲートウェイの残りの部分については[セキュリティ](/ja/docs/reference/security/)を参照してください。

## トラブルシューティング {#troubleshooting}

| 問題 | 対処法 |
|---|---|
| `droidpier mcp` がゲートウェイが動いていないため終了する | `droidpier start` でゲートウェイを起動し、クライアントを再接続してください。 |
| ツールがデバイスが接続されていないと表示する | ページを開いてデバイスに切り替えてください。 |
| ツールがページを見つけられない | `list_pages` を再実行してください: ページはアプリが開閉するたびに現れたり消えたりします。 |
| iOS ページでツールがタイムアウトする | ページがデバッガーで停止している可能性があります（例: H5 コンソールのブレークポイント）。そちらで再開してください。 |
