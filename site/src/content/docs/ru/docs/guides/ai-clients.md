`droidpier mcp` подключает ИИ-клиент, поддерживающий Model Context Protocol (MCP), например Claude Code, к шлюзу. Клиент может работать с устройством, которое показывает страница: получать список его H5-страниц, выполнять JavaScript в одной из них, читать консоль и делать скриншот.

Клиент работает через шлюз, а не открывает собственное соединение для отладки. Это важно для симуляторов iOS: WebKit позволяет только одному отладчику одновременно подключиться к странице, поэтому отдельный инструмент (например, iwdp) и H5-консоль страницы вытесняют друг друга. Через шлюз ИИ-клиент и H5-консоль совместно используют одно соединение.

## Что нужно {#what-you-need}

- Шлюз работает — в фоне (`droidpier start`) или в окне терминала. Фоновый шлюз обновляется автоматически; для MCP нужна версия, опубликованная 2026-11-24 или позже. Чтобы обновить шлюз, запущенный в окне терминала, снова выполните команду установки.
- Страница открыта и показывает устройство, которое должен использовать клиент.

## Добавление в клиент {#add-it-to-your-client}

В Claude Code достаточно добавить один раз:

```sh
claude mcp add droidpier -- droidpier mcp
```

После этого начните новую сессию Claude Code: инструменты появятся как `mcp__droidpier__…`.

Другие клиенты используют сервер, который запускается как команда и общается через стандартный ввод-вывод. Укажите полный путь к исполняемому файлу, так как приложение, запущенное из Dock, может не иметь `~/.local/bin` в `PATH`:

```json
{
  "mcpServers": {
    "droidpier": { "command": "/Users/<вы>/.local/bin/droidpier", "args": ["mcp"] }
  }
}
```

Если шлюз работает на другом порту, добавьте его: `droidpier mcp --port 7310`.

## Инструменты {#the-tools}

| Инструмент | Что делает |
|---|---|
| `device_status` | Устройство, которое показывает страница: имя, платформа (`android` или `ios`), тип и размер экрана в пикселях. |
| `list_pages` | H5-страницы на этом устройстве, каждая со значением `page`, заголовком, адресом, приложением и признаком переднего плана. |
| `evaluate` | Выполняет выражение JavaScript на странице и возвращает результат в формате JSON. Ожидает promise. Если выражение выбрасывает исключение, инструмент завершается с ошибкой. |
| `console_logs` | Вывод консоли и необработанные ошибки страницы. Сбор начинается при первом обращении инструмента к этой странице; на симуляторах iOS включает также ранее записанные сообщения. Хранит последние 500 записей. Передайте значение `next` из предыдущего ответа как `since`, чтобы получить только новые строки. |
| `screenshot` | Экран устройства в виде PNG-изображения. |

`evaluate` и `console_logs` используют значение `page` из `list_pages`. Без него они берут страницу на переднем плане; если таких страниц несколько, завершаются с ошибкой и перечисляют их для выбора.

## Какое устройство и какие страницы {#which-device-and-which-pages}

Инструменты всегда используют устройство, которое показывает страница. Чтобы использовать другое устройство, переключитесь на него на странице. Если страница не открыта — берётся устройство, к которому шлюз подключался последним; если его нет, об этом сообщается.

Страницы — это те, которые устройство разрешает видеть отладчику:

- На Android-эмуляторах и телефонах: вкладки Chrome и WebView приложений, включивших отладку WebView.
- На симуляторах iOS: вкладки Safari и `WKWebView`, у которых установлен `isInspectable` (iOS 16.4 и новее).

## Использование рядом с H5-консолью {#using-it-next-to-the-h5-console}

ИИ-клиент и H5-консоль страницы могут одновременно отлаживать одну и ту же страницу. То, что записывает клиент, также появляется в H5-консоли.

Если открыть или закрыть H5-консоль на странице симулятора iOS, которую также использует клиент, шлюз снова открывает соединение отладки страницы, чтобы консоль начала работу с чистого листа и ничего не оставила после себя (например, паузы перед загрузкой следующей страницы). Вызов инструмента, выполняющийся в этот момент, завершится ошибкой; клиент может повторить его.

Когда шлюз перезапускается (например, для обновления), `droidpier mcp` продолжает работать и подключается снова, как только шлюз вернётся, в течение минуты. Вызов, выполняющийся в этот момент, завершится ошибкой.

## Безопасность {#security}

`droidpier mcp` подключается к шлюзу через Unix-сокет `~/Library/Application Support/Droidpier/mcp-<port>.sock`. Открыть его папку может только ваш пользователь macOS. Шлюз не открывает для него сетевой порт, и веб-страницы не могут до него добраться.

Любая программа, работающая от вашего пользователя, может использовать этот сокет, как могла бы запустить `adb` или `simctl` напрямую. Клиент с этими инструментами может выполнять произвольный JavaScript на H5-страницах ваших устройств, включая страницы, на которых вы авторизованы. Разрешайте инструменты в клиенте так же, как разрешаете другие инструменты, выполняющие код.

Остальное о шлюзе — в разделе [Безопасность](/ru/docs/reference/security/).

## Устранение неполадок {#troubleshooting}

| Проблема | Что сделать |
|---|---|
| `droidpier mcp` завершается, потому что шлюз не запущен | Запустите шлюз командой `droidpier start`, затем переподключите клиент. |
| Инструменты сообщают, что устройства не подключены | Откройте страницу и переключитесь на устройство. |
| Инструмент не может найти страницу | Снова выполните `list_pages`: страницы появляются и исчезают по мере того, как приложения их открывают и закрывают. |
| Инструмент превышает таймаут на странице iOS | Страница может быть приостановлена в отладчике, например на точке останова в H5-консоли. Возобновите выполнение там. |
