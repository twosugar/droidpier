`droidpier mcp`는 Model Context Protocol (MCP)을 지원하는 AI 클라이언트(예: Claude Code)를 게이트웨이에 연결합니다. 클라이언트는 페이지가 보여 주는 기기를 살펴볼 수 있습니다. H5 페이지 목록 조회, 페이지에서 JavaScript 실행, 콘솔 읽기, 스크린샷 촬영이 가능합니다.

클라이언트는 자체 디버그 연결을 열지 않고 게이트웨이를 통해 접근합니다. iOS 시뮬레이터에서 이 점이 중요합니다. WebKit은 한 번에 한 디버거만 페이지에 연결할 수 있으므로, 별도의 도구(예: iwdp)와 페이지의 H5 콘솔이 서로를 밀어냅니다. 게이트웨이를 통하면 AI 클라이언트와 H5 콘솔이 하나의 연결을 공유합니다.

## 필요한 것 {#what-you-need}

- 게이트웨이가 실행 중이어야 합니다. 백그라운드(`droidpier start`) 또는 터미널 창 중 하나. 백그라운드 게이트웨이는 자동으로 업데이트됩니다. MCP는 2026-11-24 이후에 게시된 버전이 필요합니다. 터미널 창에서 실행 중인 게이트웨이를 업데이트하려면 설치 명령을 다시 실행하세요.
- 페이지가 열려 있고 클라이언트가 사용할 기기가 표시되어 있어야 합니다.

## 클라이언트에 추가하기 {#add-it-to-your-client}

Claude Code에서 한 번만 추가합니다.

```sh
claude mcp add droidpier -- droidpier mcp
```

이후 새 Claude Code 세션을 시작하세요. 도구들이 `mcp__droidpier__…`로 나타납니다.

다른 클라이언트는 명령으로 실행되고 표준 입출력으로 통신하는 서버를 사용합니다. Dock에서 실행된 앱은 `PATH`에 `~/.local/bin`이 없을 수 있으므로 실행 파일의 전체 경로를 입력하세요.

```json
{
  "mcpServers": {
    "droidpier": { "command": "/Users/<당신>/.local/bin/droidpier", "args": ["mcp"] }
  }
}
```

게이트웨이가 다른 포트에서 실행 중이라면 추가하세요: `droidpier mcp --port 7310`.

## 도구 {#the-tools}

| 도구 | 기능 |
|---|---|
| `device_status` | 페이지가 표시하는 기기: 이름, 플랫폼(`android` 또는 `ios`), 종류, 픽셀 단위 화면 크기. |
| `list_pages` | 해당 기기의 H5 페이지. 각 페이지에 `page` 값, 제목, 주소, 앱, 포그라운드 여부가 포함됩니다. |
| `evaluate` | 페이지에서 JavaScript 표현식을 실행하고 결과를 JSON으로 반환합니다. Promise를 기다립니다. 표현식이 오류를 발생시키면 도구가 그 오류와 함께 실패합니다. |
| `console_logs` | 페이지의 콘솔 출력과 처리되지 않은 오류. 도구가 해당 페이지를 처음 사용할 때 수집이 시작됩니다. iOS 시뮬레이터에서는 이전에 기록된 메시지도 포함됩니다. 최근 500개를 유지합니다. 이전 응답의 `next` 값을 `since`로 전달하면 새 줄만 가져옵니다. |
| `screenshot` | 기기 화면을 PNG 이미지로 반환합니다. |

`evaluate`와 `console_logs`는 `list_pages`의 `page` 값을 사용합니다. 없으면 포그라운드 페이지를 사용합니다. 여러 페이지가 포그라운드에 있으면 실패하고 선택할 페이지 목록을 보여 줍니다.

## 어떤 기기와 페이지를 사용하는가 {#which-device-and-which-pages}

도구는 항상 페이지가 표시하는 기기를 사용합니다. 다른 기기를 사용하려면 페이지에서 해당 기기로 전환하세요. 열린 페이지가 없으면 게이트웨이가 마지막으로 연결한 기기를 사용하고, 없으면 그렇다고 알려 줍니다.

페이지는 기기가 디버거에게 보여 주는 것들입니다.

- Android 에뮬레이터 및 스마트폰: Chrome 탭, WebView 디버깅을 켠 앱의 WebView.
- iOS 시뮬레이터: Safari 탭, `isInspectable`을 설정한 `WKWebView`(iOS 16.4 이상).

## H5 콘솔 옆에서 사용하기 {#using-it-next-to-the-h5-console}

AI 클라이언트와 페이지의 H5 콘솔이 같은 페이지를 동시에 디버그할 수 있습니다. 클라이언트가 기록한 내용도 H5 콘솔에 나타납니다.

클라이언트도 사용하는 iOS 시뮬레이터 페이지에서 H5 콘솔을 열거나 닫으면, 게이트웨이가 페이지의 디버그 연결을 다시 열어 콘솔이 깨끗하게 시작되고 아무것도 남기지 않게 합니다(예: 다음 페이지가 로드되기 전 일시 정지). 그 순간 실행 중인 도구 호출은 실패합니다. 클라이언트가 다시 실행할 수 있습니다.

게이트웨이가 재시작할 때(예: 자동 업데이트), `droidpier mcp`는 계속 실행되며 게이트웨이가 돌아오면 최대 1분 안에 다시 연결합니다. 그 순간 실행 중인 호출은 실패합니다.

## 보안 {#security}

`droidpier mcp`는 Unix 소켓 `~/Library/Application Support/Droidpier/mcp-<port>.sock`을 통해 게이트웨이에 접근합니다. 해당 폴더는 macOS 사용자만 열 수 있습니다. 게이트웨이는 이를 위한 네트워크 포트를 열지 않으며 웹 페이지도 접근할 수 없습니다.

사용자 계정으로 실행되는 모든 프로그램은 이 소켓을 사용할 수 있습니다. `adb`나 `simctl`을 직접 실행하는 것과 같습니다. 이 도구들을 가진 클라이언트는 로그인된 페이지를 포함해 기기의 H5 페이지에서 임의의 JavaScript를 실행할 수 있습니다. 코드를 실행하는 다른 도구를 허용하는 방식으로 클라이언트의 도구를 허용하세요.

게이트웨이의 나머지 부분은 [보안](/ko/docs/reference/security/)을 참조하세요.

## 문제 해결 {#troubleshooting}

| 문제 | 해결 방법 |
|---|---|
| `droidpier mcp`가 게이트웨이가 실행되지 않아 종료됨 | `droidpier start`로 게이트웨이를 시작한 뒤 클라이언트를 다시 연결하세요. |
| 도구가 연결된 기기가 없다고 함 | 페이지를 열고 기기로 전환하세요. |
| 도구가 페이지를 찾을 수 없음 | `list_pages`를 다시 실행하세요: 앱이 열고 닫힘에 따라 페이지도 나타나고 사라집니다. |
| iOS 페이지에서 도구가 시간 초과됨 | 페이지가 디버거에서 일시 정지되어 있을 수 있습니다(예: H5 콘솔의 중단점). 거기서 재개하세요. |
