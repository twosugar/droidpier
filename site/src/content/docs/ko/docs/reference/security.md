페이지는 `droid.devpier.dev`에서 제공되지만, 에뮬레이터와 게이트웨이는 내 Mac에서 실행됩니다. 열어 둔 어떤 웹 페이지든 Mac의 프로그램에 연결을 시도할 수 있으므로, 게이트웨이는 모든 연결을 검사합니다.

## 루프백 전용

게이트웨이는 `127.0.0.1`에서만 수신합니다. 로컬 네트워크나 인터넷에서 오는 연결은 받지 않습니다. 다른 컴퓨터는 게이트웨이에 접근할 수 없습니다.

## Origin 허용 목록

<!-- verify: phase 3 -->
브라우저는 페이지가 WebSocket을 열 때 `Origin` 헤더를 보내며, 웹 페이지는 이를 위조할 수 없습니다. 게이트웨이는 `droid.devpier.dev`의 공개 페이지와 게이트웨이 자신의 로컬 페이지에서 오는 연결만, 즉 다음 Origin만 허용합니다:

- `https://droid.devpier.dev`
- `http://127.0.0.1:<port>`
- `http://localhost:<port>`

<!-- verify: phase 3 -->
그 밖의 Origin이거나 Origin이 없는 연결은 코드 `4003`으로 닫힙니다. 다른 사이트의 페이지는 포트를 추측하더라도 에뮬레이터를 제어할 수 없습니다.

## 페이지가 게이트웨이를 찾는 방법

<!-- verify: phase 3 -->
- 응답하는 게이트웨이가 없는 동안 `droid.devpier.dev/app/`의 페이지는 1초마다 게이트웨이를 확인하고, `droidpier`가 실행되는 즉시 연결합니다. 탭이 백그라운드에 있는 동안에는 확인하지 않습니다.
- 페이지는 포트 `7300` 또는 주소의 `#port=` 뒤에 있는 포트를 사용합니다. 게이트웨이는 포트 `7300`에서 실행되지 않을 때만 여는 주소에 `#port=<port>`를 붙입니다.
- 페이지는 포트를 브라우저에 저장하지 않습니다.

## 웹사이트는 Mac에 연결하지 않습니다

<!-- verify: phase 3 -->
Chrome의 로컬 네트워크 권한과 게이트웨이의 Origin 검사는 모두 경로 단위가 아니라 사이트 단위로 동작합니다. 따라서 문서 페이지는 `/app/`의 에뮬레이터 페이지와 권한을 공유합니다. 그 영향을 줄이기 위해:

- `/app/`의 에뮬레이터 페이지만 게이트웨이에 연결합니다. 홈 페이지와 이 문서는 절대 연결하지 않으므로, 이를 읽어도 권한 요청이 뜨지 않습니다.
- 사이트는 서드파티 스크립트, 스타일, 글꼴, 미디어를 로드하지 않습니다. 모든 것이 `droid.devpier.dev`에서 제공됩니다.

## 소프트웨어 설치

<!-- verify: phase 3 -->
게이트웨이는 묻지 않고 Android SDK 패키지를 설치하거나 기기를 만들지 않습니다. 설치나 기기 생성은 무엇을 어디에 다운로드하는지 페이지에 표시된 뒤, 페이지에서 직접 확인합니다. 페이지는 Google 라이선스를 전문으로 보여 주고, 동의한 항목만 설치합니다. 명령줄 도구 23 이상 버전은 묻지 않고 라이선스에 동의할 수 있으며, 이 경우 확인 전에 페이지가 알려 줍니다. 게이트웨이는 터미널에서 아무것도 묻지 않습니다.

## 연결 종료 코드

<!-- verify: phase 3 -->
| 코드 | 의미 |
|---|---|
| `4000` | 첫 메시지가 `hello`가 아니었습니다. |
| `4002` | 페이지와 게이트웨이가 서로 다른 프로토콜 버전을 사용합니다. |
| `4003` | 허용되지 않은 Origin입니다. |
