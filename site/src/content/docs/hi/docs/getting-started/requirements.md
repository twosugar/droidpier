Droidpier आधिकारिक Android एमुलेटर को आपके अपने Mac पर चलाता है और उसे ब्राउज़र के एक टैब में दिखाता है। किसी रिमोट सर्वर पर कुछ नहीं चलता। आप एक छोटा लोकल प्रोग्राम (गेटवे) इंस्टॉल करते हैं, और उसी Mac पर आपको Android एमुलेटर और एक सिस्टम इमेज चाहिए।

## कंप्यूटर

- Apple Silicon (M1 या उसके बाद का) वाला Mac। वर्शन 1 सिर्फ़ Apple Silicon Mac और arm64 सिस्टम इमेज को सपोर्ट करता है।
- वर्शन 1 में Intel Mac, Windows और Linux सपोर्टेड नहीं हैं।

## ब्राउज़र

- Google Chrome या Microsoft Edge।
- Safari और Firefox सपोर्टेड नहीं हैं। कारण के लिए [ब्राउज़र सपोर्ट](/hi/docs/reference/browser-support/) देखें।

## Android SDK के कंपोनेंट

गेटवे Android SDK के इन हिस्सों का इस्तेमाल करता है:

| कंपोनेंट | किसलिए | अनुमानित डाउनलोड साइज़ |
|---|---|---|
| `emulator` | Android वर्चुअल डिवाइस चलाता है | लगभग 400 MB |
| `system-images;android-34;google_apis;arm64-v8a` | Android 14 (API 34) सिस्टम इमेज | लगभग 1.5 GB |

आपको Android Studio खोलने की ज़रूरत नहीं है। अगर आपके पास Android Studio से पहले से SDK है, तो गेटवे उसी का इस्तेमाल करता है। यह SDK को इस क्रम में ढूँढता है:

1. `ANDROID_HOME` environment variable में दी गई डायरेक्टरी।
2. `~/Library/Android/sdk`।

<!-- verify: phase 3 -->
अगर कुछ मौजूद नहीं है, तो गेटवे आपको बताता है कि क्या नहीं है और कुछ भी डाउनलोड करने से पहले आपसे पूछता है। [पहली बार चलाना](/hi/docs/getting-started/first-run/) देखें।

## मेमोरी

<!-- verify: phase 3 -->
हर चल रहा एमुलेटर उतनी RAM इस्तेमाल करता है जितनी उसके डिवाइस कॉन्फ़िगरेशन में सेट है। गेटवे जो डिफ़ॉल्ट डिवाइस बना सकता है, वह 4096 MB इस्तेमाल करता है। एक समय में एक ही डिवाइस दिखाया जाता है।

## मापा गया प्रदर्शन {#measured-performance}

M4 Mac पर Pixel 5 API 34 वर्चुअल डिवाइस (1080×2340) के साथ Chrome 157 में, rgba-mmap फ़्रेम ट्रांसपोर्ट (shared memory के ज़रिए raw RGBA फ़्रेम) इस्तेमाल करते हुए, स्क्रीन मीडियन 60 फ़्रेम प्रति सेकंड की दर से अपडेट हुई, और टैप लेटेंसी p50 पर 20 ms और p90 पर 30 ms रही। आपके आँकड़े आपके Mac, डिवाइस और ब्राउज़र पर निर्भर करते हैं।

CPU को इसी सेटअप पर लगातार 16 स्वाइप के दौरान मापा गया, जिसमें एमुलेटर, गेटवे और डिस्प्ले प्रोसेस (सभी Chrome प्रोसेस) को जोड़ा गया। Droidpier ने 257% इस्तेमाल किया (एमुलेटर 136% + गेटवे 69% + Chrome 52%)। scrcpy ने, इसी तरीक़े से और इसी एमुलेटर के साथ मापने पर, 208% इस्तेमाल किया (एमुलेटर 203% + scrcpy 5%), यानी Droidpier ने scrcpy के CPU उपयोग का 1.24 गुना CPU इस्तेमाल किया।
