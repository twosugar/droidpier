`droidpier mcp` एक AI क्लाइंट को जो Model Context Protocol (MCP) बोलता है, जैसे Claude Code, गेटवे से जोड़ता है। क्लाइंट फिर पेज पर दिखने वाले डिवाइस को देख सकता है: उसके H5 पेजों की सूची बनाएँ, किसी पेज में JavaScript चलाएँ, कंसोल पढ़ें और स्क्रीनशॉट लें।

क्लाइंट अपना खुद का डीबगिंग कनेक्शन खोलने की बजाय गेटवे के ज़रिए जाता है। iOS सिमुलेटर पर यह ज़रूरी है: WebKit एक बार में सिर्फ़ एक डीबगर को पेज से जोड़ने देता है, इसलिए एक अलग टूल (जैसे iwdp) और पेज का H5 कंसोल एक-दूसरे को हटा देते हैं। गेटवे के ज़रिए AI क्लाइंट और H5 कंसोल एक ही कनेक्शन साझा करते हैं।

## आपको क्या चाहिए {#what-you-need}

- गेटवे चल रहा हो, बैकग्राउंड में (`droidpier start`) या Terminal विंडो में। बैकग्राउंड गेटवे खुद अपडेट होता है; MCP को 2026-11-24 या बाद का वर्शन चाहिए। Terminal विंडो में चल रहे गेटवे को अपडेट करने के लिए इंस्टॉल कमांड फिर से चलाएँ।
- पेज खुला हो और उस डिवाइस को दिखाता हो जिसे आप क्लाइंट से इस्तेमाल कराना चाहते हैं।

## अपने क्लाइंट में जोड़ें {#add-it-to-your-client}

Claude Code में, एक बार जोड़ें:

```sh
claude mcp add droidpier -- droidpier mcp
```

इसके बाद एक नया Claude Code सेशन शुरू करें: टूल्स `mcp__droidpier__…` के रूप में दिखेंगे।

दूसरे क्लाइंट एक ऐसे सर्वर का उपयोग करते हैं जो कमांड के रूप में चलता है और standard input/output से बात करता है। पूरा executable पाथ दें, क्योंकि Dock से खुले ऐप के `PATH` में `~/.local/bin` नहीं हो सकता:

```json
{
  "mcpServers": {
    "droidpier": { "command": "/Users/<आप>/.local/bin/droidpier", "args": ["mcp"] }
  }
}
```

अगर गेटवे दूसरे पोर्ट पर चल रहा है तो जोड़ें: `droidpier mcp --port 7310`.

## टूल्स {#the-tools}

| टूल | क्या करता है |
|---|---|
| `device_status` | पेज पर दिखने वाला डिवाइस: नाम, प्लेटफ़ॉर्म (`android` या `ios`), प्रकार और पिक्सल में स्क्रीन साइज़। |
| `list_pages` | उस डिवाइस के H5 पेज, हर एक में `page` वैल्यू, टाइटल, पता, ऐप और क्या यह फ़ोरग्राउंड में है। |
| `evaluate` | किसी पेज में JavaScript expression चलाता है और नतीजा JSON में देता है। Promise का इंतज़ार करता है। अगर expression error फेंके तो टूल उस error के साथ fail हो जाता है। |
| `console_logs` | किसी पेज का कंसोल आउटपुट और uncaught errors। पहली बार जब कोई टूल उस पेज का इस्तेमाल करे तब collect शुरू होता है; iOS सिमुलेटर पर पहले के log किए message भी शामिल होते हैं। आख़िरी 500 रखता है। नई lines पाने के लिए पिछले जवाब की `next` वैल्यू `since` के रूप में पास करें। |
| `screenshot` | डिवाइस स्क्रीन, PNG image के रूप में। |

`evaluate` और `console_logs` को `list_pages` की `page` वैल्यू चाहिए। बिना इसके फ़ोरग्राउंड वाला पेज इस्तेमाल होता है; कई पेज फ़ोरग्राउंड में हों तो fail होते हैं और चुनने के लिए पेज सूचीबद्ध करते हैं।

## कौन सा डिवाइस और कौन से पेज {#which-device-and-which-pages}

टूल्स हमेशा वही डिवाइस इस्तेमाल करते हैं जो पेज दिखाता है। दूसरा डिवाइस इस्तेमाल करने के लिए पेज में उसपर स्विच करें। कोई पेज न खुला हो तो गेटवे ने जिस डिवाइस से आख़िरी बार connect किया वह इस्तेमाल होता है, कोई न हो तो बताता है।

पेज वे हैं जो डिवाइस किसी डीबगर को देखने देता है:

- Android एमुलेटर और फ़ोन पर: Chrome tabs, और उन ऐप्स के WebViews जो WebView debugging चालू करते हैं।
- iOS सिमुलेटर पर: Safari tabs, और `WKWebView`s जो `isInspectable` सेट करते हैं (iOS 16.4 और बाद के)।

## H5 कंसोल के साथ इस्तेमाल {#using-it-next-to-the-h5-console}

AI क्लाइंट और पेज का H5 कंसोल एक ही पेज को एक साथ डीबग कर सकते हैं। क्लाइंट जो log करता है वह H5 कंसोल में भी दिखता है।

iOS सिमुलेटर पेज पर H5 कंसोल खोलने या बंद करने पर (जिसे क्लाइंट भी इस्तेमाल कर रहा है), गेटवे पेज का डीबगिंग कनेक्शन फिर से खोलता है ताकि कंसोल साफ़ शुरू हो और कुछ न छूटे (जैसे अगले पेज लोड होने से पहले रुकना)। उस वक्त चल रहे टूल call fail हो जाते हैं; क्लाइंट उन्हें फिर चला सकता है।

जब गेटवे खुद को update करने के लिए restart होता है, `droidpier mcp` चलता रहता है और गेटवे वापस आने पर, एक मिनट तक, फिर connect हो जाता है। उस वक्त चल रहे call fail हो जाते हैं।

## सुरक्षा {#security}

`droidpier mcp` गेटवे तक Unix socket `~/Library/Application Support/Droidpier/mcp-<port>.sock` के ज़रिए पहुँचता है। सिर्फ़ आपका macOS उपयोगकर्ता इसका फ़ोल्डर खोल सकता है। गेटवे इसके लिए कोई network port नहीं खोलता, और web pages इस तक नहीं पहुँच सकते।

आपके उपयोगकर्ता के रूप में चलने वाला कोई भी प्रोग्राम इस socket का इस्तेमाल कर सकता है, जैसे वह `adb` या `simctl` खुद चला सकता था। इन टूल्स वाला क्लाइंट आपके डिवाइसों के H5 पेजों में — जिनमें लॉग इन पेज भी शामिल हैं — कोई भी JavaScript चला सकता है। क्लाइंट में इन टूल्स को उसी तरह allow करें जैसे आप code चलाने वाले दूसरे टूल्स को करते हैं।

गेटवे की बाकी जानकारी के लिए [सुरक्षा](/hi/docs/reference/security/) देखें।

## समस्या निवारण {#troubleshooting}

| समस्या | क्या करें |
|---|---|
| `droidpier mcp` गेटवे न चलने के कारण बंद हो गया | `droidpier start` से गेटवे शुरू करें, फिर क्लाइंट को फिर से connect करें। |
| टूल्स कहते हैं कोई डिवाइस connect नहीं | पेज खोलें और डिवाइस पर switch करें। |
| टूल को पेज नहीं मिला | `list_pages` फिर चलाएँ: पेज ऐप्स के खुलने-बंद होने पर आते-जाते रहते हैं। |
| iOS पेज पर टूल timeout हुआ | पेज डीबगर में pause हो सकता है, जैसे H5 कंसोल के किसी breakpoint पर। वहाँ से resume करें। |
